# 关键窗口方法 V2：修改、复现实验与效果诊断

日期：2026-07-16

## 1. 结论

V2 相比 V1 **有改进，但改进幅度不足以通过有效性门槛**，所以本轮结论仍为 `REVISE`，暂不建议把主要精力转向 LinuxCNC 集成。

- 相对最强的误差峰值窗口，关键误差 AUC 的配对中位改善率从 V1 的 **-4.02%** 提高到 V2 的 **-1.57%**，差距缩小 2.45 个百分点，但仍未反超。
- 配对胜率从 **26.67%** 提高到 **30.00%**，仍低于预设的 60% 门槛。
- 约束求解成功率仍为 **100%**。
- 相对误差峰值基线的全局误差倍率从 **0.996** 降到 **0.871**；V2 没有以更坏的全局误差换取局部效果。
- V2 已超过全轨迹、曲率、jerk 和随机窗口基线，但误差峰值窗口仍是必须正面解决的强基线。

因此，准确表述应是：**下一步决策有效地改进了原方法，但还没有把论文主张证明到位。**

## 2. 本轮修改

原 V1 使用固定人工权重组合绝对误差、误差变化率、曲率和 jerk，并以 `eta=0.30` 作为主方法。V2 做了三项修改：

1. 增加真实的名义控制灵敏度特征，即名义模型下“样条控制变量对轮廓误差的影响强度”。
2. 用非负逻辑排序权重替代固定人工权重；输入特征为绝对误差、误差变化率、曲率、jerk 和名义控制灵敏度。
3. 采用严格的留一轨迹族校准：每次只用另外四类轨迹和独立校准机床域拟合权重，在被留出的轨迹族及六个测试机床域上冻结测试；主方法使用 `eta=1.0`。

测试集合、30 个轨迹—机床配对案例、每次 4 轮 ILC、窗口预算、虚拟机床域和预设门槛全部保持不变。V2 只是增加一个新方法，因此 V1/V2 可在完全相同案例上直接配对比较。

## 3. V1 与 V2 的直接配对比较

| 指标 | V1：固定自动窗口，eta=0.30 | V2：校准自动窗口，eta=1.0 | 变化 |
|---|---:|---:|---:|
| 中位归一化关键误差 AUC | 0.3736 | 0.3718 | 降低 0.0018 |
| 相对误差峰值的配对中位改善率 | -4.02% | -1.57% | +2.45 个百分点 |
| 相对误差峰值的胜率 | 26.67% | 30.00% | +3.33 个百分点 |
| 与评估窗口的中位 IoU | 0.500 | 0.784 | +0.284 |
| 约束求解成功率 | 100% | 100% | 不变 |
| 相对误差峰值的全局误差倍率 | 0.996 | 0.871 | 改善 |

以 30 个相同案例直接比较 V2 与 V1 主方法：

- V2 的配对中位 AUC 改善率为 **2.38%**；
- V2 胜率为 **63.33%**；
- 单侧 Wilcoxon 符号秩检验 `p=0.0460`；
- 配对中位改善率的 bootstrap 95% 区间为 **[-0.54%, 4.47%]**。

这说明 V2 相对 V1 的方向是正确的，但统计证据仍属边界水平：Wilcoxon 检验刚达到 0.05，而 bootstrap 区间仍包含 0，不能把它描述成稳定的大幅提升。

## 4. V2 与各基线的结果

以下均为 30 个相同案例上的配对结果，正值表示 V2 的关键误差 AUC 更低。

| 对比方法 | 中位 AUC 改善率 | V2 胜率 | 中位全局误差倍率 | 结论 |
|---|---:|---:|---:|---|
| 曲率窗口 | +11.15% | 96.67% | 0.881 | 明确优于 |
| jerk 窗口 | +4.23% | 73.33% | 0.885 | 优于 |
| 随机窗口 | +18.55% | 86.67% | 0.889 | 明确优于 |
| 全轨迹 ILC | +3.92% | 73.33% | 1.150 | 优于 |
| 误差峰值窗口 | **-1.57%** | **30.00%** | **0.871** | 仍未优于 |

V2 对误差峰值窗口的 bootstrap 95% 区间为 **[-4.35%, -0.29%]**，在当前门槛和当前样本中，差距并非由少数异常案例造成。

按轨迹族拆分后，V2 相对误差峰值窗口的结果为：

| 轨迹族 | 配对中位 AUC 改善率 | 胜出案例 |
|---|---:|---:|
| ellipse | -0.29% | 2/6 |
| figure_eight | -4.40% | 0/6 |
| harmonic_loop | -5.50% | 2/6 |
| rounded_square | -2.33% | 1/6 |
| s_curve | +0.76% | 4/6 |

问题主要集中在 `figure_eight`、`harmonic_loop` 和 `rounded_square`，而不是所有轨迹都同样失败。

## 5. 为什么 IoU 大幅提高，AUC 却仍未超过误差峰值

五次留一轨迹族校准得到的平均特征权重及其占总权重比例为：

| 特征 | 平均权重 | 相对占比 |
|---|---:|---:|
| 绝对误差 | 2.471 | 50.98% |
| 曲率 | 1.156 | 23.84% |
| 误差变化率 | 0.584 | 12.06% |
| 名义控制灵敏度 | 0.353 | 7.29% |
| jerk | 0.282 | 5.83% |

名义控制灵敏度被学习器保留了，但作用明显小于绝对误差和曲率。更关键的是，本轮学习目标仍是“某个采样点是否落入评估窗口”，而论文真正关心的是“选择该窗口后，有限次 ILC 能使关键误差 AUC 降低多少”。二者不是同一个优化目标。

这解释了当前现象：V2 将窗口 IoU 从 0.500 提高到 0.784，却没有同步获得对误差峰值基线的 AUC 优势。换句话说，**V2 更会模仿评估窗口，但还没有学会直接选择最有优化收益的窗口。**

此外，评估窗口本身有 85% 的分数来自独立校准域的共识误差，因此测试域的误差峰值天然是一个高度对齐且合理的强基线。这个基线必须保留，不能为了让方法通过而删除。

## 6. 下一步决策

建议把 V2 固定为论文消融版本，下一轮只修改“窗口学习目标”，暂时不扩展 LinuxCNC：

1. 在校准域枚举候选窗口，对每个候选执行一次或少量 ILC 更新，直接记录其真实收益 `Delta J`。
2. 将学习任务从点级二分类改为候选窗口的 listwise/pairwise 排序，预测“单位窗口预算带来的关键误差 AUC 降幅”。
3. 以误差峰值窗口为硬负样本或残差基线，学习“何时偏离误差峰值能获得额外收益”，而不是从头模仿窗口标签。
4. 把早期收敛收益加入训练目标，因为当前主指标是 4 轮学习曲线的 AUC，而不仅是最终一次误差。
5. 继续使用相同 30 个冻结测试案例和相同门槛；新方法只有在超过误差峰值后，才进入 LinuxCNC/虚拟控制器集成阶段。

这条 V3 路线更接近计算机领域中的决策学习、排序学习和仿真驱动优化，也比继续手调特征权重更有论文价值。
